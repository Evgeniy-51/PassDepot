# PassDepot

[English](README_EN.md)

**PassDepot** — приложение для Windows, предназначенное для безопасного хранения паролей и заметок. Данные шифруются master password и сохраняются в локальном файле `.pd`. При необходимости зашифрованная копия может синхронизироваться с приватным Git-репозиторием (GitHub, GitLab).

Текущая версия: **v0.2**

## Возможности

- **Несколько независимых профилей** — у каждого свой master password и своё хранилище.
- **Два режима хранения:**
  - только локально (без Git);
  - локально + синхронизация через Git-репозиторий.
- **Структура данных:** папки → записи (название, логин, пароль, заметки).
- **Шифрование** файла хранилища `.pd` (Argon2id + XChaCha20-Poly1305).
- **Синхронизация с Git:** сохранение (commit + push), обновление (pull), повторная отправка при сбое сети.
- **Импорт и экспорт:**
  - зашифрованного хранилища `.pd`;
  - метаданных профиля в JSON (без секретов).
- **Интерфейс:** русский и английский языки, три темы оформления.
- **Автоблокировка** сессии по таймауту неактивности.
- **Смена master password** и переименование профиля без потери данных.
- **Установщик Windows (NSIS)** с выбором языка и ярлыков.

## Системные требования

| Компонент | Требование |
|-----------|------------|
| ОС | **Windows 11** (целевая платформа) |
| WebView2 | Обычно уже установлен в Windows 11; установщик при необходимости загрузит runtime |
| Git | **Только для профилей с Git-синхронизацией** — [Git for Windows](https://git-scm.com/download/win), доступен в `PATH` |
| Сеть | Нужна для clone/pull/push Git-профилей; локальный режим работает офлайн |

Для **локального профиля** Git и интернет не требуются.

## Установка

### Установщик (рекомендуется)

1. Запустите `PassDepot-amd64-installer.exe` из каталога `build/bin/` (или из релиза).
2. Выберите язык установщика (русский / English).
3. Укажите каталог установки (по умолчанию: `C:\Program Files\PassDepot`).
4. На последнем шаге отметьте при необходимости:
   - ярлык в меню «Пуск»;
   - ярлык на рабочем столе.
5. Завершите установку.

При удалении программы через «Программы и компоненты» удаляются:

- файлы приложения;
- данные в `%AppData%\PassDepot`;
- сохранённые PAT в Windows Credential Manager.

**Удалённый Git-репозиторий при этом не изменяется.**

### Портативный запуск

Можно использовать один файл `PassDepot.exe` без установщика. Каталоги данных создаются автоматически при первом запуске (см. [Где хранятся данные](#где-хранятся-данные)).

## Быстрый старт

### Первый запуск

1. Запустите PassDepot.
2. Нажмите **«Добавить профиль»**.
3. На вкладке **«Новый профиль»** укажите:
   - имя профиля;
   - master password (не менее 8 символов) и повтор;
   - режим хранения (локальный или с Git).
4. Нажмите **«Сохранить»** — откроется хранилище.

### Создание записи

1. Создайте **папку** (кнопка «Новая папка»).
2. Выберите папку.
3. Нажмите **«Новая запись»**, заполните поля и подтвердите изменения (✓).
4. Нажмите **«Сохранить»** (или «Сохранить файл»), чтобы записать изменения в `.pd`.

Подробная справка по созданию профиля и настройке Git — в файле [`_создание_профиля.md`](_создание_профиля.md) и в встроенной кнопке **«Помощь»** на экране создания профиля.

## Режимы хранения

### 1. Только локальное хранилище

- Все данные хранятся на этом компьютере в `%AppData%\PassDepot\vaults\<id>.pd`.
- Git, PAT и репозиторий **не нужны**.
- Синхронизация между устройствами **не выполняется автоматически** — перенос через экспорт/импорт `.pd`.

**Подходит для:** одного ПК, офлайн-работы, минимальной настройки.

### 2. Локально + Git-репозиторий

- Локальная копия: `%AppData%\PassDepot\repos\<id>\` (клон репозитория).
- В репозитории лежит **только зашифрованный** файл `.pd`.
- Для доступа к Git нужен **PAT** (Personal Access Token), сохраняемый в Windows Credential Manager.
- Кнопка **«Сохранить»** записывает vault локально и отправляет изменения в репозиторий (commit + push).
- Кнопка **«Обновить»** подтягивает изменения с сервера (если нет несохранённых локальных правок).

**Подходит для:** нескольких компьютеров, резервной копии вне диска, истории коммитов в Git.

## Работа с данными

### Основные действия в интерфейсе

| Действие | Описание |
|----------|----------|
| **Сохранить** | Записывает изменения в локальный `.pd`; для Git-профиля — также commit и push |
| **Обновить** | Подтягивает vault из репозитория (только если нет несохранённых локальных изменений) |
| **Повторить push** | Повторная отправка в Git, если предыдущий push не удался, но файл уже сохранён локально |
| **Выйти** | Завершает сессию, очищает расшифрованные данные из памяти |

### Состояния синхронизации (Git-профиль)

- **Несохранённые изменения** — есть правки в памяти, не записанные в файл.
- **Не отправлено в репозиторий** — файл сохранён локально, но push не прошёл; доступна кнопка «Повторить push».

### Аккаунт / настройки профиля

- смена master password;
- переименование профиля;
- настройка автоблокировки (минуты бездействия);
- смена URL репозитория, ветки, PAT (с миграцией vault при смене репозитория);
- экспорт хранилища и профиля;
- удаление профиля **только локально** (удалённый репозиторий не трогается).

## Импорт и экспорт

### Импорт

На экране **«Добавить профиль»** → вкладка **«Импорт»**:

| Тип | Что делает |
|-----|------------|
| **Импорт хранилища** (`.pd`) | Создаёт новый локальный профиль из зашифрованного файла; имя можно задать перед импортом |
| **Импорт профиля** (JSON) | Добавляет профиль с настройками репозитория; PAT и master password вводятся отдельно |
| **Импорт из текста** | То же, что импорт JSON, через вставку содержимого |

### Экспорт

В **Аккаунте** профиля:

| Тип | Содержимое |
|-----|------------|
| **Экспорт хранилища** (`.pd`) | Зашифрованный vault; для переноса или резервной копии |
| **Экспорт профиля** (JSON) | Имя, URL репозитория, ветка — **без PAT и master password** |

### Перенос на другой компьютер

**Локальный профиль:**

1. Экспорт `.pd` на старом ПК.
2. На новом ПК: импорт `.pd`, вход с тем же master password.

**Git-профиль:**

1. Экспорт JSON профиля (или создание профиля с теми же URL/веткой).
2. На новом ПК: импорт JSON, ввод **нового PAT** и master password.
3. При входе vault подтянется из репозитория.

> PAT в экспорт не включается — на каждом компьютере рекомендуется свой токен с минимально необходимыми правами.

## Безопасность

### Шифрование

- Формат контейнера: бинарный файл `.pd` (magic `PDVT`, версия 1).
- **KDF:** Argon2id — из master password выводится ключ шифрования.
- **AEAD:** XChaCha20-Poly1305 — аутентифицированное шифрование; подмена файла обнаруживается при расшифровке.
- У каждого сохранения — свой salt и nonce.

### Секреты

| Секрет | Где хранится |
|--------|----------------|
| Master password | **Нигде не сохраняется** — вводится при каждом входе |
| Содержимое vault | Только в зашифрованном `.pd` на диске и (опционально) в Git |
| Git PAT | Windows Credential Manager (`PassDepot/PAT/<profileId>`) |
| Экспорт профиля (JSON) | Без PAT и master password |

### Сессия

- Расшифрованные данные находятся **только в оперативной памяти** на время работы с открытым профилем.
- При выходе, закрытии приложения или автоблокировке сессия сбрасывается, ключ и содержимое очищаются.
- Буфер обмена очищается при выходе из профиля.

### Рекомендации

- Используйте **длинный уникальный** master password; без него восстановить `.pd` невозможно.
- Данные, раскрытие которых способно причинить реальный вред, храните в отдельном профиле (только локальное хранилище, без синхронизации с Гит-рипозиторием)
- Не храните master password и PAT вместе с экспортом профиля.

## Где хранятся данные

Корневой каталог (по умолчанию):

```
%AppData%\PassDepot\
```

| Путь | Назначение |
|------|------------|
| `profiles.json` | Список профилей (имена, URL репозитория, ветка; без секретов) |
| `vaults\<profileId>.pd` | Локальные vault-файлы (режим «только локально») |
| `repos\<profileId>\` | Локальные клоны Git-репозиториев |

Для тестов и отладки можно переопределить корень переменной окружения `PASSDEPOT_DATA_ROOT`.

При **установке через NSIS** каталог `%AppData%\PassDepot` создаётся автоматически при первом использовании; отдельная настройка не требуется.

## Сборка из исходников

### Требования для разработки

- [Go](https://go.dev/) 1.23+
- [Node.js](https://nodejs.org/) (LTS) и npm
- [Wails CLI](https://wails.io/docs/gettingstarted/installation) v2.12+
- Для установщика: [NSIS](https://nsis.sourceforge.io/) 3.x (`makensis` в `PATH`)

### Клонирование и зависимости

```powershell
git clone <url-репозитория> PassDepot
cd PassDepot
cd frontend
npm install
cd ..
```

### Режим разработки

```powershell
wails dev
```

### Сборка приложения

```powershell
wails build
```

Результат: `build\bin\PassDepot.exe`

### Сборка установщика (NSIS)

```powershell
wails build -clean -nsis -webview2 download
```

Результат: `build\bin\PassDepot-amd64-installer.exe`

> Файл `build\windows\installer\project.nsi` должен быть сохранён в **UTF-8 с BOM**, иначе кириллица в установщике отобразится некорректно.

### Тесты

```powershell
go test ./...
```

## Архитектура проекта

```
PassDepot/
├── main.go                 # Точка входа Wails; флаг --uninstall-cleanup для деинсталлятора
├── wails.json              # Конфигурация Wails (имя, версия, сборка frontend)
├── frontend/               # React + TypeScript (Vite)
│   └── src/
│       ├── App.tsx         # Основной UI
│       ├── i18n/           # Локализация ru/en
│       └── theme.ts        # Темы оформления
├── internal/
│   ├── vaultcore/          # Модель vault, шифрование .pd
│   ├── profile/            # Профили, profiles.json, импорт/экспорт JSON
│   ├── credstore/          # PAT в Windows Credential Manager
│   ├── gitremote/          # Обёртка над git.exe (clone, pull, push)
│   └── appshell/           # Wails API, сессия, синхронизация
└── build/
    ├── bin/                # Собранные exe и installer
    └── windows/installer/  # NSIS-скрипт установщика
```

**Стек:** Go (backend) + Wails v2 + React + WebView2.

**Модель синхронизации (Git):** без merge в памяти — `Refresh` полностью заменяет локальный vault версией из репозитория; конфликты разрешаются правилом «сначала сохрани локальные изменения».

## Ограничения и известные особенности

- Платформа: **только Windows** (сборка и тестирование ориентированы на Win11).
- Git-профили требуют установленного `git.exe` в PATH.
- Одновременная работа с одним vault с нескольких устройств без координации может привести к расхождению версий; последний успешный push «побеждает» при обновлении.
- Удаление профиля в приложении **не удаляет** файл vault из удалённого репозитория (история Git сохраняется).
- Имена профилей должны быть **уникальными** (без учёта регистра).
